# 公開準備（Google Play）

> 開発者向けの手順書。GitHub Pages の公開対象からは外している（`docs/_config.yml` の `exclude`）。

## 1. 署名とビルド（EAS）

- アプリ ID（Android）: `app.kakitome`。**ストアに出すと変更できない。**
- Expo のプロジェクト: `@donchan/kakitome`（`app.json` の `owner` と `extra.eas.projectId`）
- 署名は EAS に任せる。初回の `eas build` で、EAS がアップロード鍵を作って管理する（手元に鍵ファイルは要らない）。**最初の 1 回は対話が必要**なので、手元のターミナルで実行する
- 構築: `eas build -p android --profile production`（AAB が出る）。バージョン番号（`versionCode`）は EAS が自動で増やす（`eas.json` の `appVersionSource: remote` と `autoIncrement`）。表示用のバージョンは `app.json` の `expo.version`
- アップロード鍵（EAS が作成・管理）の SHA-1: `C4:E4:29:7B:3D:04:B4:C1:8C:0A:D8:A1:DE:51:0B:F8:D6:DB:C0:60`（初回ビルド `1be5f9b9` の AAB の署名から取得。`eas credentials -p android` でも見られる）。Google Cloud の OAuth に使う（下の 2 章）。Play に登録後、Play 経由で配布されるアプリの署名鍵は別の SHA-1 になる
- 権限は必要最小限に絞ってある（`app.json` の `blockedPermissions`）。リリースの権限: INTERNET / SCHEDULE_EXACT_ALARM / VIBRATE / ACCESS_NETWORK_STATE / ACCESS_WIFI_STATE / RECEIVE_BOOT_COMPLETED / POST_NOTIFICATIONS / WAKE_LOCK
- ローカルのリリースビルド（動作確認用）は、署名が debug になる。Play への提出には使わない

### 提出（`eas submit`）

- 前提: Play Console でアプリを**手動で作成**してある、Google サービスアカウントの鍵を EAS に登録してある（`eas credentials` か Expo のダッシュボード）
- サービスアカウントは設定済み（2026-10-04）。鍵（JSON）は EAS のサーバーに登録してあり、リポジトリには置かない。初回の登録は対話のみで、`--non-interactive` では設定できない
- 実行: `eas submit -p android --profile production`。内部テストの下書きとして提出される（`eas.json`）。提出できるのは AAB のみ
- 提出後は、ストア掲載などを終えるまで下書きのまま

## 2. Google Cloud（OAuth）

1. 「Android」の OAuth クライアントに、SHA-1 を**追加**する（既存のデバッグ用 SHA-1 は消さない）
   - アップロード鍵: 上の SHA-1（`C4:E4:29:…:C0:60`）。EAS の production ビルドを、手元の端末に直接入れて試すときに使う
   - **Play アプリ署名の鍵**: `57:FD:81:3F:DB:C4:59:F3:3B:46:75:3B:EF:61:17:CF:D4:FB:BE:7F`（Play 経由でインストールされたアプリが使う。Play Console の「アプリの署名」に表示される。「アプリの完全性」は「Google Play による保護」に移った）
2. 「Google Auth Platform」→「対象」で、公開ステータスを「テスト」から「本番」へ。要求するスコープは `drive.appdata`（非センシティブ）と基本情報のみ
3. 「ブランディング」: アプリ名、サポートメール（Google グループ `kakitome-app-support@googlegroups.com`。選べるのはログイン中のアカウントか、管理者になっているグループのみ。外部からの投稿を許可しておく）、アプリのホームページ（`https://kakitome.d0nchan.com/`）、プライバシーポリシー（`.../privacy`）
   - 承認済みドメインには `d0nchan.com` を登録する（`github.io` は公開サフィックスのため使えない可能性があり、独自ドメイン `kakitome.d0nchan.com` で公開している）。所有確認は Search Console の「ドメイン」プロパティ（`d0nchan.com`）で行う。Cloudflare の DNS に TXT レコード（`@`、`google-site-verification=…`）を追加して確認する。未確認だとブランディングの確認で「ホームページのウェブサイトが登録されていません」と出て、本番にできない
4. 本番にした後、テストユーザー以外の Google アカウントでサインインできることを確認する

## 3. プライバシーポリシーの公開

- 文面: `docs/privacy.md`（連絡先メールアドレスを書き入れてから公開する）
- GitHub のリポジトリ → Settings → Pages → Source を「Deploy from a branch」、Branch を `main` / `/docs` にする
- URL: `https://kakitome.d0nchan.com/privacy`（独自ドメイン。`docs/CNAME`。旧 `suyama-daichi.github.io/kakitome/…` はこちらへリダイレクトされる）
- DNS は Cloudflare の CNAME `kakitome` → `suyama-daichi.github.io`。**プロキシは無効（灰色の雲、「DNS のみ」）にすること**。プロキシ（オレンジの雲）にすると、次の 2 つの問題が起きる
  - Cloudflare のメールアドレス難読化（Security → Settings の Email Address Obfuscation）で、プライバシーポリシーの連絡先が HTML 上で「[email protected]」に置き換わり、JavaScript を実行しないクローラーや審査では連絡先が見えなくなる
  - GitHub 自身の証明書が発行されず、「Enforce HTTPS」が使えない（旧 URL のリダイレクト先が `http://` になる）
- 現在の状態（確認済み）: GitHub の証明書は承認済みで「Enforce HTTPS」が有効。`http://` と旧 URL は `https://kakitome.d0nchan.com/…` へ到達する。`design` と `release` は 404（非公開）。連絡先は HTML に平文で入っている

## 4. Play Console

- 開発者アカウントの登録（登録料 25 ドル）。個人アカウントは、本番公開の前にクローズドテスト（一定人数・一定期間）が求められる場合がある。**最新の要件を Play Console で確認する**
- アプリのコンテンツ: プライバシーポリシーの URL、広告なし、データセーフティ、コンテンツのレーティング（IARC の質問票）、ターゲット層
- **アプリのアクセス権**: 「すべての機能が、特別なアクセスなしで利用できる」を選ぶ。アカウントなしでメモ・チェックリスト・画像・リマインド・ウィジェットのすべてが使え、Google サインインは同期（任意）のためだけにあるため。審査用のログイン情報（ユーザー名とパスワード）は入力しない。Google アカウントのパスワードを渡すのは避ける
  - 前提: OAuth の同意画面が「本番」であること。「テスト」のままだと、テストユーザー以外はサインインで 403 になり、審査担当者の目に不具合として映る
- **正確なアラーム**: `SCHEDULE_EXACT_ALARM` を宣言している。`USE_EXACT_ALARM` はアラーム・カレンダーアプリ限定で、本アプリは使わない。Play が申告フォームを求める場合は、用途として下記を書く
  - 「ユーザーが設定したリマインドを、指定した時刻に通知するため。許可は任意で、許可しない場合は少し遅れて通知される。設定画面から、ユーザーが明示的に許可する」
- データセーフティ（公式の定義: 「収集」は端末の外へデータを送ること。ユーザー自身のクラウドストレージ（Google ドライブ）へ直接アップロードし、開発者が受け取らないデータは申告不要。任意の Google サインインのメールアドレスは「任意」で申告する）
  - 「収集または共有するか」: **はい**（メールアドレスのため。安全側）
  - 転送中の暗号化: はい（HTTPS）
  - データの種類: 個人情報 → **メールアドレス** のみ。収集: はい、共有: いいえ、必須か任意か: **任意**（サインインしなくても使える）、一時的な処理: いいえ（サインイン情報が端末に残る）、目的: アプリの機能・アカウント管理
  - ほかの種類（名前・写真・ファイルなど）は付けない。メモ・画像・リマインドは、端末内または本人のドライブにだけあり、開発者は受け取らない
  - 迷う点: 「Google サインインだけで、メールアドレスの申告が要るか」は公式の要約からは断定できない。「いいえ」で通る可能性もあるが、申告漏れのほうが審査で指摘されやすいので「はい」を選ぶ。後から変更できる
  - アカウントの作成方法: 「ユーザーによるアカウントの作成をアプリで許可していない」だけにチェック（アプリ独自のアカウントはなく、Google の既存アカウントでサインインするだけ）。「アプリ外で作成したアカウントでログインできるか」は **はい**（Google アカウントでサインインして同期できるため）
  - 削除: 「データの削除をリクエストする方法を提供しているか」は **はい**。URL は `https://kakitome.d0nchan.com/privacy#情報の削除`。開発者のサーバーにデータはなく、端末はアンインストール、ドライブ上のデータは「非表示のアプリデータを削除」で、ユーザー自身が消せる（プライバシーポリシーの「情報の削除」に記載）

## 5. 掲載文の下書き

- アプリ名（30 文字以内）: `kakitome - ウィジェットで操作できるメモ`
- 短い説明（80 文字以内）: `ホーム画面のウィジェットから、チェックの付け外しができるチェックリストメモ。アプリを開く必要はありません。`
- 詳しい説明:

```
kakitome（書き留め）は、ホーム画面のウィジェットからチェックを操作できる、チェックリスト中心のメモアプリです。買い物リストなどの項目を、アプリを開かずに付けたり外したりできます。

■ ウィジェットで操作（Android）
・ホーム画面のウィジェットで、項目をタップするだけで完了と未完了を切り替えられます
・完了した項目は自動で下へ移ります
・ウィジェットごとに、表示するメモを選べます（選ばない場合は、メモ一覧の先頭のメモです）
・操作の結果は、アプリ本体にもすぐ反映されます

■ そのほかの機能
・メモとチェックリスト
・リマインド（毎日・毎週・毎月・毎年の繰り返しに対応）
・画像の添付（位置情報などの付加情報は取り除いて保存）
・複数の端末での同期（任意）

■ サーバーを持たない設計
メモは、まず端末の中に保存されます。複数の端末で使いたいときだけ、ご自身の Google ドライブにある、このアプリ専用の領域（アプリ以外からは見えません）に同期できます。開発者のサーバーはなく、開発者があなたのデータを受け取ることはありません。広告や利用状況の追跡もありません。

■ 同期について
・設定から Google アカウントでサインインすると始まります（サインインしなくても使えます）
・同じメモを複数の端末で同時に編集して内容が食い違ったときは、どちらも失われず、あとで見比べて選べます

プライバシーポリシー: https://kakitome.d0nchan.com/privacy
```
